# lmg-format

Rust reader/writer for **LMG Lean**, the compact on-disk form of a trained LMG scene.

An LMG model is a triangle mesh plus Gaussian splats anchored to its faces. A splat's position, size and orientation all follow from the triangle it sits on, so Lean doesn't store them. This crate recomputes them.

## Layout

```
src/lib.rs          bundle read/write, metadata
src/derive.rs       recompute positions, scales, rotations
src/ply.rs          binary PLY mesh reader
src/bin/lmg.rs      `lmg inspect`
tests/conformance.rs
tests/vectors/      fixtures, generated by the Python side
```

`derive.rs` mirrors `prepare_scaling_rot`, `update_alpha` and `_calc_xyz` in `games/mesh_splatting/scene/gaussian_mesh_model.py`, plus `rot_to_quat_batch` in `utils/general_utils.py`. If those change, this changes too and `format_version` goes up.

A bundle is a directory:

```
bicycle_distortion_r4.lmg/
  mesh.ply             triangle mesh, binary little-endian, vertex-coloured
  scene.safetensors    appearance + parameters the mesh can't imply
```

## Full vs Lean

Training writes **Full**, and still does. Lean is an export step on a finished checkpoint, produced by `lmg_format` on the Python side. This crate only ever sees Lean.

```
<mesh>.ply                                 in the mesh library, not the run directory
output/<exp>/<scene>/<cfg>/point_cloud/iteration_<N>/
  point_cloud.ply                          every splat, 62 floats each
  model_params.pt                          torch.save, i.e. a Python pickle
```

Full repeats a lot: `point_cloud.ply` stores positions, scales and rotations that get recomputed from the mesh on load anyway, plus an all-zero `normals` field. `model_params.pt` stores a budget for every face in the mesh when about 1% of faces carry a splat. It's also a pickle, so reading it means running Python — which is why the conversion lives there and everything downstream reads Lean.

Lean is 1.9x to 2.3x smaller on real checkpoints and converts back bit-for-bit. Dropped:

| dropped | recomputed from |
| --- | --- |
| `xyz` `[N,3]` | barycentric coordinates on the anchor triangle |
| `normals` `[N,3]` | always zero |
| `scaling` `[N,3]` | the triangle's edge lengths |
| `rotation` `[N,4]` | the triangle's normal and edges; all splats on a face share one |
| `triangle_indices` `[N]` | the budget array |
| `alpha_indices` `[N]` | the budget array |
| `_alpha` `[N,3]` | a shared position pool, when splats use one |
| `_scale` `[N,1]` | omitted when every splat size is 1.0 |
| dense budgets `[F]` | stored as pairs for occupied faces only |

The last three are conditional. The encoder checks each and stores the real array if a checkpoint disagrees, so the file is lossless either way; the metadata records which path it took.

## The file

`scene.safetensors` holds named arrays. `N` splats, `F` mesh faces, `K` faces carrying at least one splat, `P` positions in the shared pool.

| array | shape | type | present |
| --- | --- | --- | --- |
| `f_dc` | `[N,3]` | f32 | always — base colour |
| `f_rest` | `[N,45]` | f32 | always — higher SH bands, ~90% of the file |
| `opacity` | `[N,1]` | f32 | always |
| `budget_face_id` | `[K]` | u32 | always |
| `budget_count` | `[K]` | u8 or u16 | always, width picked from the largest budget |
| `alpha_pool` | `[P,3]` | f32 | `barycentric_mode == "pool"` |
| `alpha` | `[N,3]` | f32 | `barycentric_mode == "raw"` |
| `scale` | `[N,1]` | f32 | `scale_mode == "raw"` |
| `hover` | `[N,1]` | f32 | `model_variant == "hover"` |
| `round_id` | `[N]` | u8 | if trained progressively |

Metadata (safetensors requires string values):

| key | meaning |
| --- | --- |
| `format_version` | bumped when the derivation changes |
| `model_variant` | `binding` (splats on the surface) or `hover` (offset along the normal) |
| `sh_degree` | read from the source PLY, not assumed |
| `num_splats`, `num_faces` | `N` and `F` |
| `barycentric_mode` | `pool` or `raw` |
| `scale_mode` | `unit` or `raw` |
| `mesh_sha256` | of `mesh.ply` as written; checked on open |
| `mesh_normalized` | whether the mesh was rewritten as the model sees it |
| `mesh_file` | `mesh.ply` |
| `source` | where it came from |

Arrays are stored one field at a time, not one splat at a time, so any single field is a contiguous byte range the header points at. You can read `f_dc` without touching `f_rest`.

Two things about the mesh. It's written as the model sees it rather than copied from the mesh library, because the Python mesh loader merges near-duplicate vertices and the pre-merge file would give slightly different triangles here. And vertex colours are the texture — these meshes have no UVs — so they're carried through; a mesh without them still anchors splats correctly but renders grey.

A run directory doesn't record which mesh it used, so the conversion step is told explicitly and stamps the hash here. That hash is what stops you rendering a model against the wrong mesh.

## Using it

```toml
[dependencies]
lmg-format = { path = "../LMG_Codebase/rust/lmg-format" }
```

```rust
use lmg_format::Bundle;

let bundle = Bundle::open(std::path::Path::new("bicycle_distortion_r4.lmg"))?;
let d = bundle.derive()?;

// d.xyz              [N] splat centres
// d.scaling          [N] log-space scales, as the rasterizer wants them
// d.rotation         [N] quaternions, real part first
// d.triangle_indices [N] anchor face per splat
// d.alpha_indices    [N] pool slot per splat

// appearance comes straight off the bundle
// bundle.f_dc, bundle.f_rest, bundle.opacity, bundle.round_id
```

`derive()` reads `mesh.ply` and checks its hash; `derive_with_mesh(&mesh)` skips the read if you already hold the mesh. `write_params(&bundle, path)` writes the params file back out, keeping metadata keys this crate doesn't model.

```
cargo run --release --bin lmg -- inspect path/to/scene.lmg
```

Errors are `String`. Malformed input returns an error rather than panicking — truncated bodies, out-of-range face indices, bad element counts, unknown modes and future `format_version`s are all covered by a test.

## Limits

- Can't create a bundle from scratch — no mesh writer. It reads bundles, recomputes geometry, and rewrites the params file.
- No tiling, chunking, ordering or transport.
- Splats come out in triangle order, not importance order.
- Only binary little-endian PLY. ASCII and big-endian are rejected.

## Sample bundles

Converted from real trained scenes, kept outside the repo — tens to hundreds of megabytes, mostly mesh. Ask whoever handed you this crate for the directory.

| bundle | size | variant | modes | covers |
| --- | --- | --- | --- | --- |
| `hotdog_binding_32k` | 25M | binding | pool / unit | the common case, start here |
| `hotdog_rawalpha_32k` | 25M | binding | raw / unit | the raw-barycentric fallback |
| `hotdog_hover_80k` | 34M | hover | pool / unit | `hover` and `round_id` arrays |
| `ship_hover_80k` | 42M | hover | pool / unit | a different mesh |
| `bicycle_hover_320k` | 224M | hover | pool / unit | 320k splats, 8.8M-face mesh |

Between them: both variants, both barycentric modes, all the optional arrays. `scale_mode: "raw"` isn't represented because no trained checkpoint has produced a non-unit scale.

## Tests

```
cargo test
```

Fixtures in `tests/vectors/` are generated by the Python side through the real model code, covering `binding`, `hover`, and the fallback modes. To also run against a real scene (too large to commit):

```
python -m lmg_format.make_vectors        # regenerates the committed fixtures
LMG_REAL_VECTOR=/tmp/lmg_real_vector cargo test --release -- --nocapture
```

Tolerances aren't bit-exact, because torch accumulates sums in its own order and any other implementation differs in the last bit. Two places magnify that. Scales are stored as a log, so on thin triangles one ULP becomes ~1e-4 in log space — they're compared as actual scales instead. Rotations come from a Gram-Schmidt frame that's ill-conditioned on near-degenerate faces, giving a long tail.

Measured against a real 32k-splat scene: positions 3.6e-7, scales 2.5e-7, rotations 7.1e-5 worst case and 6.0e-7 median (about 0.008 degrees). Each field is checked on both its worst case and its median. The median matters because a real bug shifts the whole distribution, not just the tail.
